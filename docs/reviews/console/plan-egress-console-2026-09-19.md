# 出口管理：出口池存在控制台数据库，按节点和用户分配，运行中生效

- 日期：2026-09-19
- 状态：**APPROVED**（2026-09-19 操作者批准，§8 的 D-EG1～D-EG8）
- 关联：S3 合同（节点配置与 agent）、[`plan-console-phase2`](plan-console-phase2-2026-09-18.md)（控制台与 agent 同步）、
  [`review-xray-features`](review-xray-features-2026-09-19.md)（Xray 功能评估）

## 1. 目标

- 管理员在控制台维护一个**出口池**：可以放任意多个代理（第一期是 SOCKS5），看到每个代理能不能用、实际出口 IP 与所在地。
- 在某台节点上从池里选出口，**指定哪些用户**（或哪些网站、IP 段，或整台节点）走它，约一分钟内生效，不重启 Xray，用户无感。
- 每个分配有一个开关，决定出口失效时怎么办：
  - **回退直连**：效果与没有设置这个出口相同，出口恢复后自动切回。
  - **断开**：走这个出口的流量连不上，出口恢复后自动恢复。适合不希望经节点自己的 IP 出去的用途。
- **不写死任何内容**：出口、账号密码、分配关系都是数据库里的数据，程序运行时读取；代码与部署配置里不出现任何具体出口。
  新增代理类型只需加一个类型定义。

## 2. 现状（2026-09-19）

- 新系统的 SOCKS5 出口写在 `group_vars/all/socks5.yml`：出口名（`jpntt_isp`、`jp10_isp`、`dcc_test`）和对应的 vault 变量名都写死在文件里。
  新增一个出口要改这个文件、写 vault、运行 `edge.yml`，该节点 Xray 重启一次。出口不可用时，走它的流量直接失败，没有回退；
  控制台看不到任何出口信息。
- `jpntt_isp`：操作者确认已不能用，但 vault 中仍为启用，jp10 上有 4 个用户按配置走它（其中 1 人已发放新系统地址），
  这些用户在 jp10 上的连接会失败，直到这个出口被关闭。
- `jp10_isp` 配了 2 个用户但未启用；`dcc_test` 未启用。
- 旧系统有自己的 SOCKS5 出口（`reality_socks5`），不在本文范围。

## 3. 设计

### 3.1 三层：类型、出口池、分配

| 层 | 是什么 | 存在哪里 | 怎样扩展 |
|---|---|---|---|
| 出口类型 | 一种代理协议的处理方式：有哪些字段（哪些是密码）、是否支持 UDP、怎样校验、怎样生成 Xray 出口配置、怎样检测可用并取回出口 IP、怎样从链接导入 | 代码中的类型注册表，每种类型一个定义 | 新增类型 = 新增一个定义与测试 |
| 出口池 | 具体的代理：名称、类型、各字段的值、标签、备注、是否支持 UDP、启用与否 | 控制台数据库 | 页面上逐条添加，或批量导入 |
| 分配 | 某个出口用在某台节点上：分流条件、优先级、**失效时回退直连或断开** | 控制台数据库 | 分流条件按“条件类型”注册 |

- 第一期的类型只有 SOCKS5（地址、端口、账号、密码，账号密码可空）；其他类型列为后续任务。
- 第一期的条件类型：整台节点、用户（从该节点用户中选）、网站（`domain:`、`full:`、`geosite:` 写法）、IP 段（CIDR 或 `geoip:`）。
- 程序各部分只和注册表打交道，不认识具体的出口；页面表单按类型定义的字段生成。
- 部署配置中不再有出口：`edge.yml` 向控制台要这台节点的出口配置，`group_vars/all/socks5.yml` 在切换后不再用于新系统。

### 3.2 出口失效时：回退直连或断开

- 每个分配有一个开关：**回退直连**（默认）或 **断开**。
- 回退直连：agent 把这个分配的规则撤掉，流量走节点默认的直连，与没有设置出口相同；出口恢复后重新加上。
- 断开：agent 把这个分配的规则指向阻断，走这个出口的流量连不上；出口恢复后改回出口。
- 已知限制：Xray 重启后，运行中的改动要等 agent 补回（约一分钟）。上次 `edge.yml` 之后才改的分配，在这段时间里按直连；
  上次部署时已存在的分配写在节点配置里，不受影响。

### 3.3 可用性检测与切换（由节点 agent 执行）

- 检测由类型定义提供。SOCKS5：连接代理，经它访问检测地址，同时取回出口 IP 与所在地。检测地址可配置，
  默认 Cloudflare `cdn-cgi/trace`（返回 IP 与国家），也可换成自建的 IP 查询服务。
- **已分配的出口由用到它的节点检测**：有些 ISP 代理只允许指定来源 IP 连接，从控制端测不准。节点 agent 每 60 秒检测一次，结果随同步上报。
- **未分配的出口由 spt 检测**：每 10 分钟一次，页面注明“由 spt 检测”，仅供参考。
- **切换由 agent 按检测结果执行**：出口不可用时，按分配的开关撤掉规则（回退直连）或把规则指向阻断（断开）；恢复后改回。
  出口失效到切换最长约 1 分钟。出口失效与恢复都在首页提示。
- 不使用 Xray 的 observatory 与 balancer：检测与切换都在 agent 中，不需要改 Xray 配置、不需要重启，以后新增的类型也按同样方式检测。
  代价是切换依赖 agent 在运行；agent 停止时，首页已有“同步超过 5 分钟没有联系”的提醒。

### 3.4 在节点上生效

- 与用户同步相同：控制台为每台节点计算出口清单与版本号，agent 每分钟随 `/sync` 取回，版本变化或检测结果变化时，用 Xray API 在运行中修改：
  1. `ado` 新增或更新出口（先 `rmo` 同名出口）。新增的出口追加在末尾，默认出口仍是直连。
  2. 路由规则：先用 `rmrules` 删除本功能的规则和最后一条默认规则（`ruleTag: default`），再用 `adrules -append` 依次追加本功能的规则和默认规则。
     必须这样做：`adrules` 不加 `-append` 会替换整张路由表；加了 `-append` 只能追加在末尾，而默认规则会接住所有流量，排在它后面的规则永远不生效。
     封禁 BT、禁止内网、探测账号这些规则在前面，不受影响。
  3. 用 `lso`、`lsrules` 核对，报告已生效的版本。
- 已有连接按原来的出口继续，新连接按新规则走。
- Xray 重启后，运行中的改动会丢失，agent 在一分钟内重新加上。`edge.yml` 也向控制台取出口配置写进节点配置，
  两次部署之间的差异由 agent 补齐。
- 本功能的出口与规则都带固定前缀（出口 `egress-<编号>`、规则 `egress-<编号>-<序号>`），agent 只改带这个前缀的部分。

### 3.5 管理员看到什么

- **出口页**：出口池列表，可按类型、标签、可用状态筛选。每条显示名称、类型、地址与端口（账号密码只显示“已设置”）、标签、
  **可用状态**、**出口 IP 与所在地**、最近检测耗时与时间、由谁检测、用在哪些节点。可新增、编辑、停用、删除；批量导入（粘贴多行
  `socks5://账号:密码@地址:端口#名称`，由类型定义解析）。
- **节点页“出口”一节**：这台节点的分配，按优先级排列。从出口池选择（可用的在前），指定分流条件，选择失效时回退直连或断开，
  显示生效状态（已生效 / 同步中 / 出口失效已回退直连 / 出口失效已断开 / 失败原因）。
- **用户页**：在每台节点上经哪个出口，没有则为直连。
- 所有修改记入操作记录，操作记录中不出现账号密码。

### 3.6 数据与安全

- 账号密码与出口一起存在控制台数据库，随每日备份，与用户 UUID、订阅地址同等对待。页面不回显，只下发给分配了这个出口的节点，
  经现有的 `/sync` 通道（节点 token 认证、TLS）。
- agent 经 stdin 把出口配置交给 `xray api ado`，账号密码不出现在命令行与日志中。
- 现有出口不自动导入：`jpntt_isp` 已不能用；`jp10_isp`、`dcc_test` 未启用。需要时在出口页添加或批量导入。

## 4. 范围与非目标

- 范围：控制台（类型与条件注册表、出口池、分配与失效开关、出口页、节点页与用户页、`/sync` 下发与上报、首页提示）、
  节点 agent（检测、切换、运行中生效）、`edge.yml`（从控制台读取出口）、测试与文档。
- 非目标：SOCKS5 以外的类型（后续任务，逐个添加）；出口 IP 绑定与变化检测、UDP 单独处理、Xray 重启空窗期的防泄露等“固定 IP”加强
  （操作者 2026-09-19 决定暂不考虑）；多个出口分担流量；按出口统计流量；从服务商的代理列表地址自动拉取出口。

## 5. 前提与未知

1. ISP 的 SOCKS5 是否支持 UDP：分配默认只让 TCP 走出口，UDP 直连；出口支持 UDP 时可在分配上打开。
2. 每 60 秒一次检测会不会触发 ISP 的限制：检测间隔可配置。
3. 客户端发给节点的是域名还是 IP：多数客户端发域名，节点把域名交给 SOCKS5 解析；客户端自己解析成 IP 时，
   按网站分流的规则可能匹配不到（按用户分配不受影响）。本地端到端中核对。

## 6. 实施步骤与验收

1. **第一期**（SOCKS5）：类型与条件注册表，出口池与分配的数据与页面，批量导入，节点与 spt 的检测，agent 的运行中生效与切换，
   `edge.yml` 从控制台读取，首页提示。
   验收（本地端到端，含两个测试 SOCKS5，其中一个可以随时停掉）：
   - 出口页显示两个出口的可用状态与出口 IP；
   - 分配给用户 A 后一分钟内 A 经出口访问（出口 IP 与节点 IP 不同），其他用户仍直连，Xray 未重启；
   - 回退直连：停掉出口后一分钟内 A 改走直连，恢复后切回；
   - 断开：停掉出口后一分钟内 A 连不上，恢复后恢复；
   - 删除分配后恢复直连；代码与部署配置中搜不到任何具体出口。
2. **后续任务**：其他代理类型（HTTP、Shadowsocks、WireGuard/WARP 等），逐个添加类型定义。
3. **上线**：部署后在出口页添加需要的出口，再在节点上分配；确认 jp10 上已不再有 `jpntt_isp`。

## 7. 回滚

- 分配出问题：在节点页删除或停用分配，一分钟内恢复直连。
- 整体回滚：`edge_egress_source: files` 后运行 `edge.yml`，出口回到 `group_vars/all/socks5.yml` 与 vault；关闭 agent 的出口同步开关后，
  agent 不再改运行中的出口。
