# 出口管理：出口池存在控制台数据库，按节点和用户分配，运行中生效

- 日期：2026-09-19
- 状态：**APPROVED**（2026-09-19 操作者批准，§8 的 D-EG1～D-EG8；2026-09-20 补充见 §10）
- 关联：S3 合同（节点配置与 agent）、[`plan-console-phase2`](plan-console-phase2-2026-09-18.md)（控制台与 agent 同步）、
  [`review-xray-features`](review-xray-features-2026-09-19.md)（Xray 功能评估）

## 1. 目标

- 管理员在控制台维护一个**出口池**：可以放任意多个代理（第一期是 SOCKS5），看到每个代理能不能用、实际出口 IP 与所在地。
- 在某台节点上从池里选出口，**指定哪些用户**（或哪些网站、IP 段，或整台节点）走它，约一分钟内生效，不重启 Xray，用户无感。
- 每个分配有一个开关，决定出口失效时怎么办：
  - **回退直连**：效果与没有设置这个出口相同，出口恢复后自动切回。
  - **断开**：走这个出口的流量连不上，出口恢复后自动恢复。适合不希望经节点自己的 IP 出去的用途。
- **不写死任何内容**：出口、账号密码、分配关系都是数据库里的数据，程序运行时读取；代码与部署配置里不出现任何具体出口。
  新增代理类型只需加一个类型定义。

## 2. 现状（2026-09-19）

- 新系统的 SOCKS5 出口写在 `group_vars/all/socks5.yml`：出口名（`jpntt_isp`、`jp10_isp`、`dcc_test`）和对应的 vault 变量名都写死在文件里。
  新增一个出口要改这个文件、写 vault、运行 `edge.yml`，该节点 Xray 重启一次。出口不可用时，走它的流量直接失败，没有回退；
  控制台看不到任何出口信息。
- `jpntt_isp`：操作者确认已不能用，但 vault 中仍为启用，jp10 上有 4 个用户按配置走它（其中 1 人已发放新系统地址），
  这些用户在 jp10 上的连接会失败，直到这个出口被关闭。
- `jp10_isp` 配了 2 个用户但未启用；`dcc_test` 未启用。
- 旧系统有自己的 SOCKS5 出口（`reality_socks5`），不在本文范围。

## 3. 设计

### 3.1 三层：类型、出口池、分配

| 层 | 是什么 | 存在哪里 | 怎样扩展 |
|---|---|---|---|
| 出口类型 | 一种代理协议的处理方式：有哪些字段（哪些是密码）、是否支持 UDP、怎样校验、怎样生成 Xray 出口配置、怎样检测可用并取回出口 IP、怎样从链接导入 | 代码中的类型注册表，每种类型一个定义 | 新增类型 = 新增一个定义与测试 |
| 出口池 | 具体的代理：名称、类型、各字段的值、标签、备注、是否支持 UDP、启用与否 | 控制台数据库 | 页面上逐条添加，或批量导入 |
| 分流方案 | 一组网站与 IP 段，连同网络与失效时的做法；分配可引用方案，方案修改后各分配跟着变（2026-09-20 补充） | 控制台数据库 | 页面上添加 |
| 分配 | 某个出口用在某台节点上：分流条件（或一个方案）、优先级、**失效时回退直连或断开** | 控制台数据库 | 分流条件按“条件类型”注册 |

- 第一期的类型只有 SOCKS5（地址、端口、账号、密码，账号密码可空）；其他类型列为后续任务。
- 第一期的条件类型：整台节点、用户（从该节点用户中选）、网站（`domain:`、`full:`、`keyword:`、`geosite:` 写法；直接写的域名
  保存为 `domain:`）、IP 段（CIDR 或 `geoip:`）。组合方式：用户 且（网站 或 IP 段）（2026-09-20 修正，见 §10）。
- 程序各部分只和注册表打交道，不认识具体的出口；页面表单按类型定义的字段生成。
- 部署配置中不再有出口：`edge.yml` 向控制台要这台节点的出口配置，`group_vars/all/socks5.yml` 在切换后不再用于新系统。

### 3.2 出口失效时：回退直连或断开

- 每个分配有一个开关：**回退直连**（默认）或 **断开**。
- 回退直连：agent 把这个分配的规则撤掉，流量走节点默认的直连，与没有设置出口相同；出口恢复后重新加上。
- 断开：agent 把这个分配的规则指向阻断，走这个出口的流量连不上；出口恢复后改回出口。
- 已知限制：Xray 重启后，运行中的改动要等 agent 补回（约一分钟）。上次 `edge.yml` 之后才改的分配，在这段时间里按直连；
  上次部署时已存在的分配写在节点配置里，不受影响。

### 3.3 可用性检测与切换（由节点 agent 执行）

- 检测由类型定义提供。SOCKS5：连接代理，经它访问检测地址，同时取回出口 IP 与所在地。检测地址可配置，
  默认 Cloudflare `cdn-cgi/trace`（返回 IP 与国家），也可换成自建的 IP 查询服务。
- **已分配的出口由用到它的节点检测**：有些 ISP 代理只允许指定来源 IP 连接，从控制端测不准。节点 agent 每 60 秒检测一次，结果随同步上报。
- **未分配的出口由 spt 检测**：每 10 分钟一次，页面注明“由 spt 检测”，仅供参考。
- **切换由 agent 按检测结果执行**：出口不可用时，按分配的开关撤掉规则（回退直连）或把规则指向阻断（断开）；恢复后改回。
  出口失效到切换最长约 1 分钟。出口失效与恢复都在首页提示。
- 不使用 Xray 的 observatory 与 balancer：检测与切换都在 agent 中，不需要改 Xray 配置、不需要重启，以后新增的类型也按同样方式检测。
  代价是切换依赖 agent 在运行；agent 停止时，首页已有“同步超过 5 分钟没有联系”的提醒。

### 3.4 在节点上生效

- 与用户同步相同：控制台为每台节点计算出口清单与版本号，agent 每分钟随 `/sync` 取回，版本变化或检测结果变化时，用 Xray API 在运行中修改：
  1. 只替换设置变了的出口（`rmo` 后 `ado`），没变的不动；新增的出口追加在末尾，默认出口仍是直连。
  2. 路由规则：先用 `rmrules` 删除本功能的规则和最后一条默认规则（`ruleTag: default`），再用 `adrules -append` 追加本功能的规则，
     最后单独追加默认规则。出口加不上时，选了“断开”的分配改指阻断，不会变成直连（2026-09-20 修正）。
     必须这样做：`adrules` 不加 `-append` 会替换整张路由表；加了 `-append` 只能追加在末尾，而默认规则会接住所有流量，排在它后面的规则永远不生效。
     封禁 BT、禁止内网、探测账号这些规则在前面，不受影响。
  3. 用 `lso`、`lsrules` 核对，报告已生效的版本。
- 已有连接按原来的出口继续，新连接按新规则走。
- Xray 重启后，运行中的改动会丢失：reporter 连续读不到 Xray 后重启（约 1.5–2.5 分钟），重启后的 agent 重新加上。
  这段时间按上次 `edge.yml` 写入节点配置的出口运行；两次部署之间的差异由 agent 补齐。
- 本功能的出口与规则都带固定前缀（出口 `egress-<编号>`、规则 `egress-<编号>-<序号>`），agent 只改带这个前缀的部分。

### 3.5 管理员看到什么

- **出口页**：出口池列表，可按类型、标签、可用状态筛选。每条显示名称、类型、地址与端口（账号密码只显示“已设置”）、标签、
  **可用状态**、**出口 IP 与所在地**、最近检测耗时与时间、由谁检测、用在哪些节点。可新增、编辑、停用、删除；批量导入（粘贴多行
  `socks5://账号:密码@地址:端口#名称`，由类型定义解析）。
- **节点页“出口”一节**：这台节点的分配，按优先级排列。从出口池选择（可用的在前），指定分流条件，选择失效时回退直连或断开，
  显示生效状态（已生效 / 同步中 / 出口失效已回退直连 / 出口失效已断开 / 未生效的原因 / 节点应用失败的原因）。
  出口页的按类型、标签、状态筛选尚未实现（出口数量少时不需要）。
- **用户页**：在每台节点上经哪个出口，没有则为直连。
- 所有修改记入操作记录，操作记录中不出现账号密码。

### 3.6 数据与安全

- 账号密码与出口一起存在控制台数据库，随每日备份，与用户 UUID、订阅地址同等对待。页面不回显，只下发给分配了这个出口的节点，
  经现有的 `/sync` 通道（节点 token 认证、TLS）。
- agent 经 stdin 把出口配置交给 `xray api ado`，账号密码不出现在命令行与日志中。
- 现有出口不自动导入：`jpntt_isp` 已不能用；`jp10_isp`、`dcc_test` 未启用。需要时在出口页添加或批量导入。

## 4. 范围与非目标

- 范围：控制台（类型与条件注册表、出口池、分配与失效开关、出口页、节点页与用户页、`/sync` 下发与上报、首页提示）、
  节点 agent（检测、切换、运行中生效）、`edge.yml`（从控制台读取出口）、测试与文档。
- 非目标：SOCKS5 以外的类型（后续任务，逐个添加）；出口 IP 绑定与变化检测、Xray 重启空窗期的防泄露等“固定 IP”加强
  （操作者 2026-09-19 决定暂不考虑；其中 QUIC 阻断已于 2026-09-20 加入，见 §10）；多个出口分担流量；按出口统计流量；
  从服务商的代理列表地址自动拉取出口。

## 5. 前提与未知

1. ISP 的 SOCKS5 是否支持 UDP：分配默认只让 TCP 走出口，UDP 直连；出口支持 UDP 时可在分配上打开。
2. 每 60 秒一次检测会不会触发 ISP 的限制：检测间隔可配置。
3. 客户端发给节点的是域名还是 IP：多数客户端发域名，节点把域名交给 SOCKS5 解析；客户端自己解析成 IP 时，
   按网站分流的规则可能匹配不到（按用户分配不受影响）。本地端到端中核对。

   `edge.yml` 从控制台读取，首页提示。

## 7. 回滚

- 分配出问题：在节点页删除或停用分配，一分钟内恢复直连。
- 整体回滚：`edge_egress_source: files` 后运行 `edge.yml`，出口回到 `group_vars/all/socks5.yml` 与 vault；关闭 agent 的出口同步开关后，
  agent 不再改运行中的出口。

    该出口经 Tailscale 访问，从 jp10 实测 TCP 正常，但 SOCKS5 的 UDP ASSOCIATE 被拒绝（回复码 7）；
    UDP（包括客户端的 DNS 查询）被送进出口后全部失败。原检测只测 TCP，没有发现。
  - 改动：
    - 检测在 TCP 可用时经出口发一次 DNS 查询（SOCKS5 UDP 到 1.1.1.1:53）判断是否支持 UDP，结果记入检测记录。
      TCP 失败时不测 UDP，保留上一次的结论；出口设置改动后清除结论。
    - 出口页显示 UDP 一列；最近一次检测不支持 UDP 的出口不能按“TCP 和 UDP”分配。
    - 节点上，选了“TCP 和 UDP”的分配在 UDP 不通时按失效处理（回退直连或断开），首页提醒。
  - 同时：
    - 节点页的用户列表注明“只列出这台节点上的用户”（操作者以为网页添加的用户没有显示，实际是该用户按档位不在 jp10 上）；
    - 用户列表与节点列表的表头加全选。页面安全策略由禁止一切脚本改为只允许控制台自己的脚本文件（`script-src 'self'`），
      内联脚本仍然禁止。
  - 验证：
    - 本地实测：同一个检测对允许 UDP 的 SOCKS5 判为支持，对不允许的判为不支持，对连不上的判为 TCP 失败（不测 UDP）；
    - 单元测试：控制台出口 13 项，节点侧 71 项（新增 UDP 不通时只影响选了 UDP 的分配），compose 14 项（新增：控制台镜像复制的每个文件都计入镜像标签）；
    - 控制台端到端 98/98（两个测试 SOCKS5 一个支持 UDP、一个不支持：检测结果正确，不支持的不能按“TCP 和 UDP”分配，
      支持的按“TCP 和 UDP”分配后节点检测 UDP 通过；真实镜像提供全选脚本）。
- 与本文的差异：
  - 本地两个 SOCKS5 与节点从同一公网 IP 出去，§6 的“出口 IP 与节点 IP 不同”无法在本地验证。
    端到端改为看 SOCKS5 访问日志里是否有该用户的请求；出口 IP 不同要在上线后用真实出口核对。
  - §6 的“一分钟内”：检测间隔按 D-EG5 为 60 秒，失效出口两次各 10 秒超时，从失效到切换最长约 80 秒。端到端的同步间隔为 5 秒，实测 35–36 秒。
  - 代码与部署配置中没有具体出口，只有格式示例（文档地址 203.0.113.x）；`socks5.yml` 的 profile 只在 `edge_egress_source: files`
    （§7 回滚）时使用。

## 10. 2026-09-20 补充（操作者批准）

起因：操作者要把旧系统 jp10 上的“几个网站走出口”搬到新系统，并要求排查出口的全部设计
（排查记录：[`review-egress-design-2026-09-20`](review-egress-design-2026-09-20.md)）。

- **分流方案**（操作者 2026-09-20 要求）：出口页维护方案列表（名称、网站、IP 段、网络、失效时、备注）；节点页添加分配时可选方案，
  再选用户（不选即整台节点的用户）。方案修改后，引用它的分配随之变化，各节点约一分钟内生效；有分配在用的方案不能删除。
  方案是数据库内容，第一个方案由旧系统 jp10 的配置整理后在部署后添加，不写进代码。
- **只有 TCP，阻断 QUIC**（操作者 2026-09-20 批准）：TCP 经出口；同一批网站或 IP 段的 UDP 443 被阻断，浏览器改用 TCP，
  网站只看到出口 IP；其他 UDP 照常直连。只能用于按网站或 IP 段分流。旧系统 jp10 的效果与此相同（其规则不限网络，而代理不支持 UDP）。
- **条件组合改为“用户 且（网站 或 IP 段）”**：原实现要求网站与 IP 段同时满足，几乎不会匹配；本文 §3.1 原先未规定，属实现修正。
- **排查修正**（记录中的 F1–F4、H1–H2、M1–M6、L1–L8）：UDP 检测与限制；geo 数据进入工具镜像与控制台镜像，保存前由 Xray 检查条件；
  agent 上报能力版本与应用错误；只替换变化的出口，失败时“断开”保持阻断；停用出口时“断开”的分配继续阻断；spt 检测移到独立线程；
  节点入站嗅探排除 ECH 外层名 `cloudflare-ech.com`（每台节点 Xray 重启一次）。
- 验收补充：本地端到端覆盖方案（含 `geosite:`）、阻断 QUIC 的规则、出口停用时的阻断；ECH 的路由行为以同版本 Xray 实测。
  结果（2026-09-20）：控制台出口单元测试 18 项、节点侧 75 项、compose 14 项及其余测试全部通过；节点端到端 45/45（含带出口与
  阻断 QUIC 的 golden 用例 `xray -test`）；控制台端到端 102/102（方案含 `geosite:cloudflare`，节点在运行中加上 TCP 走出口与
  UDP 443 阻断两条规则，节点上所有用户访问这些网站经出口，其他网站直连，删除后恢复直连，全程 Xray 未重启）。
