# 账号共享迹象：订阅拉取来源与同时在线处数

- 日期：2026-09-19
- 状态：操作者已决定（§5 的 D-SH1～D-SH4），本地实现与验证见 §6
- 关联：[`plan-console-phase2`](plan-console-phase2-2026-09-18.md)（用户、节点 agent）、S3 合同 §10（节点 agent）

## 1. 目标

判断一个用户的账号是否被多人共用。操作者最初设想“每个订阅链接或二维码只能用一次，一台设备一个”，讨论后改为：
订阅地址保持可重复拉取，另外提供两个信号——订阅被哪些设备拉取（A），以及同一时刻在几处在线（B）。

## 2. 为什么不做一次性订阅链接

- 客户端大约每 12 小时用同一地址更新订阅。链接一次性作废后，节点增减与凭据更换（如重置地址）用户都收不到。
- 共享通常是直接转发已导入的节点或二维码截图，里面带的是连接凭据，与订阅链接是否一次性无关。
- 用户换手机、重装应用都要重新向管理员要链接。

## 3. 做法

### 3.1 A：订阅被哪些设备拉取

- 数据：订阅服务的访问记录（每次拉取的时间、IP、客户端 User-Agent）。控制台只读。
- 近 30 天、每个用户：不同网络数（IPv4 按 /24、IPv6 按 /48 合并）、客户端种类（User-Agent 的第一个产品名，浏览器算一种）、拉取次数。
- 显示：用户列表“最后拉取”下方，用户详情的订阅地址一节。只显示数量与客户端名称，不显示 IP。
- 局限：手机换网络也会增加网络数，客户端种类更能说明设备数。

### 3.2 B：同一时刻在几处在线

- 数据源：Xray 的在线统计（节点配置中已开启 `statsUserOnline`）。`xray api statsgetallonlineusers` 列出在线用户，
  `statsonlineiplist -email <用户>` 给出该用户的在线 IP 与最后访问时间。XHTTP 经 PROXY protocol 转交，同样是客户端的真实地址。
- 节点 agent 每次同步（约 60 秒）读取一次。Xray 只在某个 IP 还有打开的连接时把它留在列表里，最后一条连接关闭即移除；
  旁边的时间是最近一次新建连接的时刻，长连接期间不会更新，所以列表里的 IP 都算“正在在线”，不按时间过滤。按 IPv4 /24、IPv6 /48 归为网络，
  用控制台下发的当日密钥做 HMAC-SHA256，截取 16 位十六进制，随 `/sync` 请求上报：`{"online": {用户: ["4:…", "6:…"]},
  "online_day": 日期}`。探测账号（`SYNC_KEEP`）不上报；IP 不离开节点。
- 控制台：`/sync` 回复中带当日密钥（由只存在控制台数据库的秘密按 UTC 日期派生）。上报按 10 分钟一段存入 `online_seen`，
  只存哈希，保留 8 天。用别的日期的密钥做的哈希（agent 还没拿到当日密钥的那一分钟）不收。
- 处数：同一段内 IPv4 网络数与 IPv6 网络数取较大者。同一住处的多台设备算一处；同一设备同时用 IPv4 和 IPv6 也算一处。
- 显示：用户列表“同时在线”一列（近 24 小时最多几处，达到阈值标黄），用户详情显示近 24 小时的最大值与近 7 天每天的最大值。
  达到阈值时首页提醒“用户 X 近 24 小时最多同时在 N 处在线，可能与他人共用”。阈值为 `console_sharing_threshold`，默认 3。
- 部署：控制台（`console.yml`）与节点工具镜像（`edge.yml`，只重建 reporter 容器，Xray 不重启）。两边可按任意顺序部署：
  旧控制台忽略新字段，旧 agent 不上报。

## 4. 范围与非目标

- 不做设备级凭据（每台设备一套订阅地址与 UUID，可限制设备数、单独停用设备），这是按设备管理的新功能，A、B 观察一段时间后再议；也不限制设备数或 IP 数（官方 Xray 没有，见 [`review-xray-features`](review-xray-features-2026-09-19.md)）。不自动停用或封禁任何用户，提醒后由操作者判断。
- 不保存、不显示原始 IP。

## 5. 操作者决定

1. **D-SH1**（2026-09-19）：不做一次性订阅链接（§2）。
2. **D-SH2**（2026-09-19）：先做 A，再做 B。
3. **D-SH3**（2026-09-19）：提醒阈值 3 处。
4. **D-SH4**（2026-09-19）：控制台与节点只显示、只上报数量或哈希，不显示、不上报 IP。

## 6. 实施与验证

- 2026-09-19 本地：
  - 单元测试：控制台 `test_sync.py` 9 项（新增密钥下发与记录、处数与提醒、页面与拉取来源）；
    节点 `test_agent.py` 8 项（新增网络哈希与上报、在线查询出错不影响同步）；其余控制台与节点测试通过。
  - 控制台端到端：真实节点 agent 上报 carol 在线（采样期间客户端保持一个连接）；用户列表显示拉取来源；节点页显示 Xray 运行状态。
    第一次运行时“在线”一项失败：agent 按最后访问时间过滤掉了早于两个同步间隔的 IP，而 Xray 的这个时间是连接建立时刻、
    连接开着时不更新（`app/stats/online_map.go`）。已改为列表中的 IP 都算在线。
    修正后又失败一次，原因在测试本身：查询用了 `db.connect(...).__enter__()`，上下文对象随即被回收并关闭了连接。改用 `with` 后端到端 75/75，carol 记为 1 处。
- 线上：待 `console.yml` 与 `edge.yml` 部署后核对。
