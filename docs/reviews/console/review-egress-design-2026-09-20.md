# 出口管理设计排查

- 日期：2026-09-20
- 状态：已处理（部署待操作者授权）
- 起因：第一个真实出口上线后，接连暴露出 UDP 与按网站分流的问题；操作者要求把出口相关的设计完整排查一遍
- 对象：[`plan-egress-console`](plan-egress-console-2026-09-19.md) 的实现（工作树，含同日新增的分流方案与“阻断 QUIC”）
- 方法：一个独立审查（只读，不了解实现过程）逐项查代码与文档；另对需要运行才能确认的点做本地实测，所用 Xray 与节点同版本（26.3.27）

## 1. 结论

发现的问题都已修正或写明限制。最重要的四项：

1. 规则里用 `geosite:` / `geoip:` 时，节点 agent 加不上规则，失败后连默认规则一起丢掉，而且不报错（H1）。
2. 浏览器用 ECH 访问 Cloudflare 后面的网站时，按网站分流会失效，流量直连（F3，实测）。ChatGPT、Claude 都在 Cloudflare 后面。
3. 新控制台配旧 agent 时，一条分配只会执行一部分（H2）。
4. 停用出口时，选了“断开”的分配会改走直连，违背“宁可断开也不换 IP”（M2）。

## 2. 发现与处理

依据：**实测** = 本地用同版本 Xray 验证；**代码** = 读代码确认。

| 编号 | 问题 | 依据 | 处理 |
|---|---|---|---|
| F1 | 方案 §3.1 要求记录出口“是否支持 UDP”，实现漏了；分配“TCP 和 UDP”到不支持 UDP 的代理后，用户的 DNS 等 UDP 全部失败 | 实测（jp10） | 检测增加 UDP（经出口发一次 DNS 查询）；不支持 UDP 的出口不能按“TCP 和 UDP”分配；UDP 不通时这类分配按失效处理 |
| F2 | 一条分配同时填网站和 IP 段时，Xray 要求两者同时满足，几乎不会匹配 | 代码 | 改为“用户 且（网站 或 IP 段）”：网站、IP 段各生成一条规则 |
| F3 | 浏览器启用 ECH 时，嗅探到的是外层名 `cloudflare-ech.com`，即使客户端请求的就是 `chatgpt.com`，路由也按外层名判断 → 直连 | 实测 | 节点入站嗅探排除 `cloudflare-ech.com`，路由改用客户端请求的目标；实测修正后走出口。代价：各节点 Xray 重启一次（入站配置变化） |
| F4 | 直接写的域名（如 `abc.com`）在 Xray 中是“包含即匹配”，会误中 `abc.com.example` | 代码 | 保存时统一为 `domain:`（该网站及子域名）；`*.abc.com` 同样处理；转为小写 |

## 3. 仍然存在的限制（写入操作手册）

- **TUN 模式的客户端把域名解析成真实 IP 时**：节点只能靠嗅探得到网站名。浏览器开着 ECH 时，嗅探只拿到外层名，按网站分流不生效。
  客户端用 fake-ip（或代理模式）时，节点收到的是域名，不受影响。
- **WebRTC**：网页脚本可以经 STUN 直接连 IP，没有网站名可匹配，走节点直连。在意的用户应在浏览器中限制 WebRTC。
- **DNS**：节点为匹配“禁止内网”规则会解析目标域名（`IPOnDemand`），解析请求从节点发出。
- **Xray 重启后的空窗**：reporter 连续三次读不到 Xray 才重启（约 1.5–2.5 分钟），期间按上次 `edge.yml` 写入的配置运行。
  上次部署之后才加的分配暂时不生效，已删除的暂时回来。

## 4. 验证

- 单元测试：控制台出口 18 项、节点侧 75 项、compose 14 项，其余控制台与订阅测试全部通过。
- 节点端到端 45/45：golden 用例（含嗅探排除项与 UDP 443 阻断规则）由同版本 Xray `xray -test` 接受。
- 控制台端到端 102/102：方案含 `geosite:cloudflare`，节点在运行中加上两条规则（TCP 走出口、UDP 443 阻断），所有用户访问这些网站
  经出口、其他网站直连，删除后恢复直连，全程 Xray 未重启；“立即检测”、UDP 判定与不支持 UDP 时的分配限制照常。

## 5. 部署影响

- 各节点入站嗅探增加排除项，下次 `edge.yml` 时**每台节点 Xray 重启一次**。
- 工具镜像与控制台镜像各增加约 30 MB（geo 数据）。
- 顺序：先 `console.yml`，再 `edge.yml`。在此之间旧 agent 只收到它能完整执行的分配（H2）。
