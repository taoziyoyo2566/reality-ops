## Intent

- **B1**：旧放大用 `max(1.0, 容器流量/统计流量)` 只增不减，把 per-user 数人为膨胀。直接采信 xray 自身的 uplink/downlink 更准；配合 A2 的"增量+pending"已能正确累计。
- **C1**：DB 已 300MB/410 万行从未清理 → 保留 cron 按天界定期 DELETE 限制行数（查询性能），`wal_checkpoint(TRUNCATE)` 限制 WAL 增长。`health` 查询加时间界用上 `idx_records_timestamp`，避免随库增长劣化。**全表 VACUUM 故意不做**（对 300MB 库会整库加锁、影响在线服务）—— 作为低频/手工运维，DELETE+checkpoint 已是日常的安全选择。
- **C2**：`/healthz` 供 systemd/外部探活；关键路径不再静默吞异常（与 agent 侧 `log()` 一致）。
