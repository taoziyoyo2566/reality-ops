# Round 7 Changelog：jp10 agent 灰度与 single stats 解析修复

- 日期：2026-06-22
- 范围：`roles/monitor/templates/agent.py.j2`、监控运维文档、部署 checklist。

## 发现

`jp10` 第一台生产 agent 灰度中，部署与权限均正常：

- `reality-monitor-agent` 已加入 docker 组。
- cron 已迁移到 `reality-monitor-agent`。
- `docker exec reality_core xray api statsquery --server=127.0.0.1:10085` 在该用户下可执行。

但初始 state 为 `{"users": {}, "pending": {}}`，服务端 `/stats/health` 中 `jp10` 仍 `stale=true`。进一步检查发现 `xray statsquery` 会返回缺少 `value` 的 stat 项，且 single 模式同时存在：

- `user>>>name.host>>>traffic>>>uplink/downlink`
- `inbound>>>user-name>>>traffic>>>uplink/downlink`

旧解析逻辑对缺失 `value` 和命名形态兼容不足，导致 agent 可能静默空采样。

## 修复

- 跳过缺少 `value`、无法转整数、或值为 0 的 stat 项。
- 兼容 `user>>>...` 与 `inbound>>>user-*` 两类单实例计数。
- 优先使用 user 维度，inbound 维度只补缺失用户/方向，避免双计。
- `get_core_stats` 异常写入 `agent.log`，避免继续静默失败。

## 验证

- 本地：agent 模板渲染、`py_compile`、`jp10` 样本解析均通过。
- 本地：`git diff --check`、`ansible-playbook deploy.yml --syntax-check` 通过。
- 现网：`jp10` 手动执行 agent 后 `traffic_cache.json` 出现用户基线；随后 `/stats/health` 显示 `jp10 last_seen_ago_sec=5`、`report_count=10`、`stale=false`。

## 后续

- 扩面前先把修复后的 agent 模板部署到灰度节点。
- 第二台建议选择 multi 模式节点，覆盖多容器日志/IP 审计路径。
